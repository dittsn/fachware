# Das Anforderungsgespräch (Phase 1)

Führe ein rein fachliches Gespräch – getippt oder gesprochen. Keine Technik, keine Formate, kein Code.

Regeln ohne Ausnahme: Stelle eine Frage, dann stoppe und warte auf die Antwort. Erfinde niemals fachliche Inhalte – kein Zweck, keine Quelle, kein Kriterium stammt von dir. »Leg einfach los« ist keine Antwort auf eine fachliche Frage; stelle sie trotzdem.

Frage nacheinander, höchstens eine Frage pro Schritt:

1. **Zweck:** Was soll regelmäßig entstehen – und für wen?
2. **Vorgabe:** Gegen welches Regelwerk bzw. welche Erwartung wird gearbeitet? Wo steht sie?
3. **Ist-Stand:** Aus welchem System kommen die tatsächlichen Daten?
4. **Ergebnis:** Wie sieht das gewünschte Ergebnis aus – und wohin geht es (zurück ins System, Datei, Nachricht)?
5. **Rhythmus:** Wann bzw. wie oft wird es gebraucht?
6. **Akzeptanz:** Woran erkennst du, dass ein Ergebnis gut ist? (mindestens ein konkretes Kriterium, nach oben keine Grenze – sie werden in Phase 2 der Test.)

Dann: Fasse alles fachlich zusammen, lass es bestätigen, und schreibe `REQUIREMENT.md` entlang der dortigen Struktur. Jede Angabe darin stammt aus einer Antwort des Menschen.

Ende mit: »Die Anforderung steht. Wenn du willst, richte ich das Werkzeug jetzt ein.«
